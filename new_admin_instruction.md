# Як додати новий тенант і адміна

Тенант (workspace) — це один канал, один рев'ювер і власний список джерел. Бот,
X-застосунок і всі налаштування синку спільні для всіх тенантів.

Деплою, зміни env-змінних і перереєстрації вебхука **не потрібно**. Тенант живий з
моменту вставки рядка в базу.

Хто що робить:

| Крок | Хто |
|---|---|
| 1. Написати боту `/start` | новий адмін |
| 2. Додати бота в канал | новий адмін (або власник каналу) |
| 3. Дістати id каналу | ти |
| 4. Вставити рядок у базу | ти |
| 5. Додати джерела | новий адмін |
| 6. Перевірити | ти |

---

## Крок 1. Адмін пише боту `/start`

**Обов'язково, і бажано першим.** Telegram забороняє боту писати першим: якщо адмін
ніколи не відкривав чат із ботом, відправка поста на рев'ю впаде з
`403 bot can't initiate conversation with a user`.

Бот нічого не відповість — так і має бути, стороннього він ігнорує. Але в логах
Vercel з'явиться рядок із його числовим id:

```
webhook.unauthorized_command  fromId: 123456789  command: "start"
```

Це `fromId` і є значення `telegram_admin_chat_id` для кроку 4.

Альтернатива: адмін сам пише `@userinfobot` і надсилає тобі свій id.

> Id юзера — **додатне** число. Id каналу — **негативне**, починається з `-100`.
> Переплутати їх місцями легко, а помилка проявиться не одразу: бот постітиме
> рев'ю в канал, а сам пост — в особисте.

---

## Крок 2. Бот у канал адміністратором

Адмін додає бота в канал і дає йому право **Post messages**. Без цього права
публікація впаде з `400 Bad Request: not enough rights`.

Більше ніяких прав боту не потрібно.

> Сам рев'ювер **не мусить** бути адміном каналу й узагалі бути в ньому. Його права
> визначає виключно рядок у базі.

---

## Крок 3. Дістати id каналу

### Якщо канал публічний

```bash
curl -s "https://api.telegram.org/bot$(grep -E '^TELEGRAM_BOT_TOKEN=' .env | cut -d= -f2-)/getChat?chat_id=@yourchannel" | jq '.result.id'
```

### Якщо канал приватний

`getUpdates` поверне `409 Conflict`, поки зареєстрований вебхук, тож його треба
тимчасово зняти:

```bash
npm run webhook:delete
```

Попроси адміна щось опублікувати в каналі, тоді:

```bash
curl -s "https://api.telegram.org/bot$(grep -E '^TELEGRAM_BOT_TOKEN=' .env | cut -d= -f2-)/getUpdates" | jq '.result[].channel_post.chat'
```

Поверни вебхук одразу:

```bash
npm run webhook:set -- https://content-arbitrary.vercel.app
```

> **Увага:** і `deleteWebhook`, і `setWebhook` викликаються з
> `drop_pending_updates: true`, тож усі апдейти за цей проміжок відкидаються.
> Натискання кнопок у цю хвилину не обробляться — рев'ювер просто натисне ще раз,
> пост залишиться в статусі `awaiting_approval`.

## Крок 4. Вставити рядок у базу

`psql` локально не встановлений, тож найпростіше через Drizzle Studio:

```bash
npm run db:studio
```

Таблиця `workspaces`, додати рядок. Або SQL:

```sql
INSERT INTO workspaces (name, telegram_chat_id, telegram_admin_chat_id)
VALUES ('другий канал', '-1001234567890', '123456789');
```

| Колонка | Що це |
|---|---|
| `name` | довільна підпис для тебе, ні на що не впливає |
| `telegram_chat_id` | id каналу з кроку 3 |
| `telegram_admin_chat_id` | id адміна з кроку 1 — це **і є** його авторизація |

`legacy_source_imported_at` вказувати не треба: імпорт env-акаунта відбувається лише
для workspace 1, і гардом там є перевірка id воркспейса в `syncPosts`, а не ця
колонка.

---

## Крок 5. Адмін додає джерела

Тепер його команди працюють. У своєму чаті з ботом:

```
/addsource @someaccount
```

Повний набір:

| Команда | Що робить |
|---|---|
| `/sources` | список джерел цього тенанта (✅ активне, ⏸ на паузі) |
| `/addsource @username` | додати акаунт |
| `/pausesource @username` | тимчасово пропускати, залишивши в списку |
| `/resumesource @username` | повернути з паузи |
| `/removesource @username` | видалити зовсім |
| `/scheduled` | що заплановано на публікацію і на коли |
| `/help` | нагадати список |

Акаунт можна писати як `@karpathy`, `karpathy` або посиланням `x.com/karpathy`.

За замовчуванням джерело дзеркалить лише пости з фото чи відео. Щоб брати й текстові пости,
натисни **⚙️ Settings** під відповіддю на `/sources` чи `/addsource` і ввімкни
**Posts without media** для потрібного акаунта (працює, якщо задано `APP_BASE_URL`). Діє на нові
пости, старі не підтягуються.

---

## Крок 6. Перевірити

Дочекатися крона (щогодини о :00 UTC) або смикнути вручну:

```bash
curl -s -m 60 -H "Authorization: Bearer $(grep -E '^CRON_SECRET=' .env | cut -d= -f2- | tr -d '"'"'"'')" "https://content-arbitrary.vercel.app/api/cron/sync" | jq '{workspaces, skippedWorkspaces, sources}'
```

`workspaces` має зрости на одиницю. Якщо новий тенант не публікується, він буде в
`skippedWorkspaces` із причиною.

Повна картина по тенантах:

```bash
curl -s -H "Authorization: Bearer $CRON_SECRET" "https://content-arbitrary.vercel.app/api/status" | jq '.workspaces'
```

У кожного тенанта є `publishable: true/false` і `unpublishableReason`, коли false.

## Якщо щось не працює

| Симптом | Причина | Що робити |
|---|---|---|
| Пост стає `failed` з `403 bot can't initiate conversation` | адмін не писав боту | адмін надсилає `/start`, потім синк ще раз |
| `400 Bad Request: not enough rights` | бот без права Post messages | дати право в налаштуваннях каналу |
| Бот мовчить на команди адміна | id у базі не збігається з реальним | звірити `telegram_admin_chat_id` із `fromId` у логах |
| `skippedWorkspaces: workspace has no telegram_chat_id` | тенант без каналу | заповнити `telegram_chat_id` |
| `skippedWorkspaces: REQUIRE_APPROVAL is on but workspace has no telegram_admin_chat_id` | тенант без рев'ювера при обов'язковому рев'ю | заповнити `telegram_admin_chat_id` |
| Рев'ю приходить у канал, а пости в особисте | id каналу й адміна переплутані | поміняти значення місцями |

## Пауза і видалення

Поставити тенанта на паузу без втрат — обнулити канал. Синк пропустить його як
ненастроєного, джерела, курсори й історія залишаться:

```sql
UPDATE workspaces SET telegram_chat_id = NULL WHERE id = 2;
```

Видалення рядка **руйнівне**. `ON DELETE CASCADE` забирає джерела, курсори **і всю
історію публікацій** (`processed_posts` разом із `telegram_messages`):

```sql
DELETE FROM workspaces WHERE id = 2;
```

Разом з історією зникає й захист від дублів: якщо створити тенанта знову з тими
самими джерелами, курсорів уже немає, і наступний синк прочитає вікно з нуля та
перепостить те, що канал уже бачив.

---

## Що варто знати заздалегідь

**Один рев'ювер на один тенант.** Пошук воркспейса по id адміна бере `LIMIT 1`. Якщо
вписати ту саму людину рев'ювером двох тенантів, вона керуватиме лише одним, і яким
саме — залежить від порядку id. Щоб одна людина вела кілька каналів, потрібна окрема
зміна: перемикач активного тенанта в командах.

**Гроші множаться на тенантів.** X-застосунок один, але курсори в тенантів окремі,
тож кожен читає таймлайн сам. Один акаунт, продзеркалений у три канали, коштує як
три канали (~$0.005 за прочитаний пост).

**`MAX_POSTS_PER_RUN` діє на кожне джерело кожного тенанта.** При значенні 10 і двох
тенантах по два джерела це до 40 постів на рев'ю за один запуск.

**env більше не керує каналом.** `TELEGRAM_CHAT_ID` і `TELEGRAM_ADMIN_CHAT_ID`
сідять **лише workspace 1**, і лише поки його колонки порожні. Щойно в рядка є
канал, рядок головний: переставиш канал у базі — env його не перезапише.

**Сторонній нічого не зможе.** Хто завгодно може відкрити бота й писати йому — у
відповідь буде тиша, бо авторизація це запит у базу по id відправника. Навіть якщо
переслати комусь пост із кнопками, натискання дасть лише
`You are not authorised to review posts.`
